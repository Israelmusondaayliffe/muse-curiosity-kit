# Muse loading and helper use

Muse selects skills through its actual account catalog and accessible skill directories. Confirm the current root, support-file reads and refresh behavior; do not assume a plugin command or infer loading from a name list. The [manifest](manifest.json) describes the expected 26 identities and does not register or install them. This account surface is distinct from Muse Code.

Read the selected entry, complete method and necessary support relative to its actual installed directory. All skills work without a mandatory router or sibling. AI Film, Gauntlet, Matt, Operating Graph and ProofLoop retain affirmative-selection gates; quotations and incidental mentions do not activate them. Native enforcement of target-host metadata is not assumed.

## Local helper routes

- **LoopKit:** author truthful `host: muse` contracts. Use [manual binding/checkpoint/resume](../../skills/loopkit/references/binding.md#personal-muse-manual-route). Explicit `--state-root` wins, then `LOOPKIT_STATE_ROOT`, then the application default `~/workspace/loopkit`. Read the exact selection, generation and pending effects before resume. Automatic Muse hooks are unsupported and refuse before input/state effects.
- **Harness Engineering:** use `hectl audit --platform muse --path PATH` for each explicitly selected file or immediate skill root. It reports identities and redacted JSON/TOML keys, not values or guessed settings. See [platform limits](../../skills/harness-engineering/references/platforms.md#personal-meta-muse-selected-path-inventory). Portable checking and explicit parity remain useful; target-native operations require the actual selected target.
- **Writing Like Me:** use `wlm.py discover --host muse --workspace PATH [--home PATH]`. It reports explicit-home/workspace VOICE/STYLE existence without reading contents, guessing a home, searching another host or writing.

Resolve each script from its actual skill directory and confirm its interpreter/dependencies. A helper result does not prove native loading, workers, provider behavior or accepted quality.

## Installation or update

When installation is explicitly requested, record the intended source and destination, inspect collisions and preserve user changes. Apply a reviewed per-file update with complete support and notices; do not blind merge-copy into a live root. Compare installed bytes and verify entry/method/support access through the host. Restore only owned changes after checking intervening edits. No new installer is provided.

## Readiness limits

Memory requires the external Claude Mem engine and supported integration. No engine is bundled; Memory stays inactive when it is absent. Do not fake recall or redirect to the account's own memory.

Gauntlet's Fable task-choice gate applies even when a target-specific filesystem probe has nothing to find. Optional Codex advisor composition remains a Codex-target method. Worker-dependent methods require real fresh-worker/result/stop support; missing capabilities remain explicit limits.

Source, generated packages, installed bytes, catalog/resource loading, metadata enforcement, execution and accepted artifacts are separate evidence. Codex/Claude checks do not qualify Muse. No automatic Muse lifecycle contract, worker schema, native metadata enforcement or context-token measurement is promised.
